Las 3 dimensiones de la solucion

El MCP opera en tres capas independientes que se complementan: ejecucion tecnica, conocimiento documental, y experiencia de ingenieria.

⚙

Dimension 1: Ejecucion

OpenServer Executor — el motor que corre los modelos

  • DoSet / DoGet / DoCmd contra PROSPER, MBAL, GAP en vivo
  • Retry inteligente con correccion automatica de variables
  • Manejo de licencias — una app a la vez, kill zombies
  • Workflows secuenciales con orden validado
  • DOWN.DATA.ADD para crear registros (no sobreescribir)

  • Variables.md — tabla de referencia rapida por seccion

  • Templates .Out pre-validados como base

Hallazgos clave de la sesion de discovery

BLOCKER

Tubing Description en PROSPER

PROSPER genera una "tubing description" interna al hacer Done en Equipment Data. No existe comando OpenServer equivalente. Workaround: usar templates .Out pre-validados.

CORREGIDO

DOWN.DATA.ADD para agregar rows

El MCP original sobreescribia indices que no existian. Ahora sabemos que hay que usar DoSet("PATH.ADD", "") para crear filas nuevas en arrays de tamanio variable.

CORREGIDO

Geothermal: MD, no TVD; TMP, no Temp

Variables correctas: GEO.DATA[i].MD (no TVD), GEO.DATA[i].TMP (no Temp), GEO.HTC (no Uval). 3 de 3 variables del MCP original eran incorrectas.

CORREGIDO

DoSlowCmd no existe en Python

El paquete openserver de Python solo tiene DoCmd, DoSet, DoGet. DoSlowCmd es del COM/VBA. Todos los scripts generados por el MCP rompian por esto.

DOCUMENTADO

MBAL.MB.VALIDATE existe

A diferencia de PROSPER, MBAL si tiene un comando VALIDATE que valida todos los objetos sin GUI. MBAL es 100% automatizable via OpenServer.

DOCUMENTADO

GAP: NEWITEM + LINKITEMS

GAP usa DoGAPFunc para NEWITEM, LINKITEMS, SOLVENETWORK. Estos retornan valores y requieren una sintaxis distinta a DoCmd.

WORKAROUND

Paths con espacios

SAVEFILE y OPENFILE fallan si el path tiene espacios sin comillas. El MCP debe siempre generar: PROSPER.SAVEFILE("path con espacios")

DOCUMENTADO

40+ variables mapeadas

Se documentaron todas las variables verificadas de PROSPER, MBAL y GAP en archivos de referencia separados, listos para ser consumidos por el RAG y el corrections cache.
