2 El truco: abstraccion de backend

Ya esta implementado. El MCP nunca llama a AWS directamente: llama a una interfaz. Cambiar de local a cloud es una variable de entorno.

# Local (default) - offline, sin costo
set PETEX_RAG_BACKEND=local
set PETEX_KB_BACKEND=local

# AWS - compartido entre el equipo
set PETEX_RAG_BACKEND=bedrock
set PETEX_BEDROCK_KB_ID=XXXXXXXXXX
set PETEX_KB_BACKEND=dynamodb
set PETEX_KB_TABLE=petex-engineering-kb
set AWS_REGION=us-east-1

# El codigo del MCP es identico. get_rag_backend() y
# get_kb_backend() devuelven el backend correcto segun la config.

petex_rag_backend.py

LocalRAGBackend (TF-IDF) ↔ BedrockRAGBackend (Retrieve API). Misma interfaz query()/find_variable().

petex_kb_backend.py

LocalKBBackend (JSON) ↔ DynamoDBKBBackend. Misma interfaz get()/put()/list_keys().

4 Costos estimados

Para un equipo chico (UDS), con uso moderado. Ordenes de magnitud, verificar precios vigentes.

Almacenamiento + indexado

S3 (PDFs, ~30MB): centavos/mes.
OpenSearch Serverless: el mayor costo fijo, ~US$ por hora de OCU. Se puede pausar.

~US$ bajo/mes fijo

Consultas (por uso)

Bedrock Retrieve: por query.
Titan Embeddings: por indexado (una vez) + queries.
DynamoDB: on-demand, centavos.

~US$ por uso

Recomendacion de costo

Arrancar en LOCAL (costo cero, ya funciona). Migrar a AWS solo cuando varios ingenieros necesiten compartir la misma KB. El mayor costo fijo es OpenSearch Serverless; una alternativa mas barata para empezar es Bedrock KB con almacenamiento vectorial en Aurora Serverless o pgvector.
