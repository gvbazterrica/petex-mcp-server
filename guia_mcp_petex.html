Guia MCP PETEX

Como se ajusto el MCP para PROSPER / MBAL / GAP y como se usa

UDS Pan Energy IPM 13.5 OpenServer

1 El proceso de ajuste

El MCP original generaba scripts "a ciegas" asumiendo nombres de variables que muchas veces no existian. El ajuste fue un proceso de discovery: ejecutar contra la licencia real, ver que rompe, buscar en la documentacion, y corregir.

Diagnostico inicial

Se intento armar un modelo integrado y fallo en casi cada paso. Los nombres de variables del MCP no coincidian con los reales de IPM 13.5.

Discovery de variables

Se probaron cientos de nombres de variables contra PROSPER en vivo, cruzando con los 4 manuales (OpenServer, PROSPER, GAP, MBAL) para encontrar los correctos.

Identificacion del blocker

PROSPER requiere un "Done" en Equipment Data (GUI) que genera la tubing description interna. No hay comando OpenServer equivalente.

Verificacion GAP en vivo

Se creo y valido una red GAP completa via OpenServer. NEWITEM y LINKITEMS funcionan con DoCmd. Se corrigieron las variables reales (File, SolverPres, Desc[]).

MCP server real

Se envolvio todo en un servidor FastMCP con 8 tools, conexion persistente, y license manager que distingue los dos tipos de error de licencia.

Blocker: Tubing Description (PROSPER)

PROSPER genera la tubing description interna al hacer "Done" en Equipment Data desde la GUI. No hay comando OpenServer. Workaround: usar templates .Out pre-validados.

MBAL y GAP: 100% automatizables

MBAL tiene MBAL.MB.VALIDATE y GAP tiene GAP.VALIDATE(0) que validan sin GUI. Solo PROSPER tiene el blocker.

3 Las capacidades inteligentes

El diferencial de la solucion: el MCP no ejecuta a ciegas. Consulta la documentacion cuando duda, aprende de sus errores, y razona decisiones de ingenieria. Estas tres piezas trabajan juntas.

RAG documental

4976 chunks de los manuales PROSPER, MBAL, GAP, OpenServer + hallazgos.

TF-IDF + coseno, 100% offline sin descargar modelos. Responde dudas sobre variables, comandos y procedimientos.

-> search_docs

Auto-correccion con aprendizaje

Arranca con 16 correcciones verificadas. Cuando una variable falla, consulta el RAG, la corrige y la aprende.

La correccion se persiste: nunca vuelve a fallar con esa variable. Se vuelve mas inteligente con el uso.

-> show_learned_corrections

Orquestador end-to-end

De una intencion de alto nivel a un modelo completo. Consulta la KB de ingenieria por correlaciones y PVT segun formacion.

Arma PROSPER-MBAL-GAP, maneja licencias, usa auto-correccion. Dry-run para revisar antes de ejecutar.

-> build_integrated_model

# El flujo del cerebro del MCP
Intencion  "pozo horizontal VM, 200 m3/d, separador 200 psi"
    |
Decision  KB de ingenieria -> VLP=PetroleumExperts2, IPR=Vogel, PVT tipico
    |
Ejecucion PROSPER -> MBAL -> GAP  (si una variable falla -> consulta RAG)
    |
Aprendizaje correccion encontrada -> persiste -> proxima vez no falla

4 Manejo de licencias

Descubrimiento importante: hay dos errores de licencia distintos que el MCP ahora distingue.

App ocupada

"could not locate a free license"

La app puntual (PROSPER/MBAL/GAP) no tiene licencia. Otra app puede estar libre. Reintentar o hacer fallback.

Pool OpenServer agotado

"No OpenServer license available"

El pool entero de OpenServer esta agotado a nivel red. Ningun cliente puede conectar. Esperar o liberar sesiones.

Las licencias fluctuan minuto a minuto. El MCP reintenta con backoff, hace fallback (si falta MBAL, sigue PROSPER-GAP), y las tools que no usan licencia (recomendaciones, lookup) siempre funcionan.

5 Escaneo exhaustivo de modelos

El MCP puede leer un modelo existente (.Out/.gap/.mbi) y devolver el inventario COMPLETO de todos sus componentes. La garantia de cobertura total viene de una arquitectura de dos capas.

Capa 1: Cobertura (que existe)

Catalogo extraido automaticamente del manual OpenServer (612 paginas). Descubre TODAS las secciones documentadas: IPR simple y multilateral, gas lift, ESP, HSP, jet pump, sucker rod, drilling, lithology, PVT correlations, y todos los nodos GAP.

Capa 2: Precision (nombres exactos)

Campos verificados de cada array, limpios del ruido que introduce el PDF. Garantiza que cada variable se lea con el nombre correcto.

# Como garantiza leer TODO
1. Catalogo AUTO del manual  -> descubre que secciones/arrays existen
2. Campos CURADOS verificados -> lee cada campo con nombre exacto
3. Recorre arrays por su .COUNT (o probe si no existe)
4. Descarta lo que da FNA/error -> robusto al ruido
5. verify_scan_coverage -> compara contra el Report nativo de PETEX
   -> lo que falte se agrega al catalogo curado

Cobertura actual: PROSPER 14 arrays + escalares (equipment, IPR multilateral, gas lift, drilling, lithology), MBAL tanks/PVT/aquifer/prediction wells, GAP todos los nodos (wells, pipes, separators, tanks, pumps, joints, groups).

5b Agente autonomo y cloud (Fases 3-4)

Las ultimas capas convierten al MCP en un agente que aprende de resultados, planifica pads completos y esta listo para la nube.

Feedback loop

Cada modelo exitoso se registra (parametros + resultados). El agente consulta esos casos para recomendar valores que YA funcionaron y estimar caudales realistas. Aprende de la realidad, no solo de la doc.

Multi-well (pads)

Planifica un pad completo: varios pozos compartiendo manifold y separador. Razona correlaciones/PVT de cada pozo segun su formacion y explica la secuencia antes de ejecutar.

Cloud-ready (AWS)

El RAG y la KB de ingenieria tienen backend intercambiable: local (offline) o AWS (Bedrock + DynamoDB). Migrar es cambiar una variable de entorno, no reescribir. Ver aws_deployment.html.

Ejecucion siempre local

OpenServer queda en la maquina del ingeniero (ahi vive la licencia PETEX). Solo el conocimiento migra a la nube y se comparte entre el equipo.

7 Las 19 tools disponibles

Una vez configurado, Kiro puede invocar estas tools en lenguaje natural. Las marcadas "sin licencia" funcionan siempre, incluso si el pool de OpenServer esta agotado.

check_licenses() usa licencia

Diagnostica que apps (PROSPER/MBAL/GAP) estan disponibles ahora. Distingue app ocupada vs pool agotado.

prosper_get_recommendations(formation, fluid) sin licencia

Consulta la knowledge base de ingenieria: que correlacion VLP e IPR usar segun formacion. Ej: "vaca_muerta", "oil".

lookup_variable(description) sin licencia

Devuelve el nombre correcto de una variable OpenServer. Ej: "geothermal temperature" -> GEO.DATA[i].TMP.

prosper_open(filepath) usa licencia

Abre un modelo PROSPER (.Out) para operar. Mantiene la sesion viva para las siguientes tools.

prosper_run_nodal(whp, correlation, water_cut, gor) usa licencia

Corre nodal analysis y devuelve el caudal operativo. Requiere prosper_open primero.

mbal_create_reservoir(...) usa licencia

Crea un reservorio MBAL con PVT, presion, OOIP. Lo valida con MBAL.MB.VALIDATE (sin GUI).

gap_build_network(...) usa licencia

Arma una red: pozo (de PROSPER) -> flowline -> separador. Opcional: conecta tank MBAL. Variables verificadas en vivo.

gap_solve(filepath, separator_name) usa licencia

Resuelve una red GAP y devuelve caudales de oil, gas y agua del separador.

search_docs(question, source) sin licencia RAG

Busca en la documentacion PETEX (4976 chunks de los 4 manuales + hallazgos) para responder cualquier duda sobre variables, comandos o procedimientos. Filtro opcional por fuente.

show_learned_corrections() sin licencia APRENDIZAJE

Muestra las correcciones de variables que el MCP tiene: las verificadas (semilla) y las que aprendio solo via RAG durante el uso. Refleja como el MCP mejora con el tiempo.

build_integrated_model(formation, fluid, target_rate, ..., execute) usa licencia ORQUESTADOR

El comando de alto nivel: a partir de una intencion (formacion, fluido, target), consulta la KB de ingenieria, elige correlaciones y PVT, arma el plan PROSPER-MBAL-GAP y lo ejecuta con auto-correccion. Por defecto hace dry-run (muestra el plan) para revisar antes de correr.

scan_model(filepath, mode) usa licencia ESCANER

Lee un modelo existente (.Out/.gap/.mbi) y devuelve el inventario COMPLETO de todos sus componentes. mode="full" recorre el catalogo exhaustivo del manual (IPR incl. multilateral, gas lift, equipment, drilling, todos los nodos GAP); "readable" da lectura limpia con labels; "both" ambos.

set_parameter(filepath, variable, value) usa licencia ESCANER

Modifica cualquier parametro de un modelo y lo guarda. Usa auto-correccion: si el nombre no es exacto, lo corrige via cache/RAG. Ej: cambiar presion de separador, skin, OOIP.

verify_scan_coverage(filepath) usa licencia ESCANER

Valida la cobertura del escaner: reporta que secciones leyo y guia para comparar contra el Report nativo de PETEX. Garantiza que no se escape ningun componente.

list_templates() / create_from_template(...) usa licencia TEMPLATES

Clona una plantilla .Out pre-validada y ajusta parametros, evitando el blocker de la tubing description de PROSPER. Permite crear modelos completos sin el paso manual del Done.

record_model_success(...) sin licencia AGENTE

Registra un modelo que corrio con exito (params + resultados). Cierra el feedback loop: el agente aprende de los modelos reales que funcionaron.

recommend_from_history(formation, fluid) sin licencia AGENTE

Recomienda parametros basados en casos exitosos PREVIOS (no solo la KB estatica). Da el rango de caudal observado en modelos que ya funcionaron.

plan_pad(pad_name, wells, separator_pressure) sin licencia AGENTE

Planifica un PAD completo (varios pozos + red compartida). Razona correlaciones/PVT de cada pozo y arma la secuencia explicada en lenguaje natural.

8 Ejemplos de uso en Kiro

Consulta de ingenieria

"Que correlacion uso para un pozo de Vaca Muerta con petroleo?"

-> prosper_get_recommendations

Nodal analysis

"Abri el APO-135 y corre el nodal a 200 psi de WHP"

-> prosper_open + prosper_run_nodal

Red de superficie

"Arma una red conectando este pozo a un separador de 200 psi a 3 km"

-> gap_build_network + gap_solve

Modelo integrado (orquestador)

"Arma el modelo completo de un pozo horizontal de Vaca Muerta de 4000m para 200 m3/d"

-> build_integrated_model (elige correlaciones, PVT y arma todo)

Duda sobre la documentacion

"Como corro una prediccion step by step en GAP?"

-> search_docs (busca en los manuales)

Ver que aprendio el MCP

"Que correcciones de variables aprendiste?"

-> show_learned_corrections

Escanear un modelo

"Escanea el APO-135 y decime que separadores, VLP e IPR tiene"

-> scan_model (inventario completo)

Modificar un parametro

"Cambia la presion del separador SEP1 a 150 psi"

-> set_parameter (con auto-correccion)

Planificar un pad completo

"Planifica un pad de 3 pozos horizontales de Vaca Muerta con un separador comun de 200 psi"

-> plan_pad (razona cada pozo + secuencia)

Aprender de resultados

"Que parametros funcionaron antes para pozos de Vaca Muerta?"

-> recommend_from_history (feedback loop)
